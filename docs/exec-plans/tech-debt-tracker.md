## 2026-11-12 项目检查

### TD-001：finalize 失败可能删除上一次成片

- 状态：已修复并验证（2026-11-12）。
- 优先级：高，影响已有产物保留。
- 位置：`src/lib/video-generator/manual/final-report.ts` 的渲染前删除和异常清理分支。
- 根因：旧成片与本次输出共用 `final.mp4`，异常分支无条件删除该路径，没有区分上次成功产物与本次临时产物。
- 已复现：在当前项目 `video-runs/` 下创建隔离 fixture，用真实 ffmpeg 生成短 MP4；调用 `finalizeManualRecording({ runDir, env: {} })`，因缺少配音密钥失败，调用前存在的成片随后不存在。未调用云端服务，临时样本已清理，真实业务产物未改动。
- 建议：先生成独立版本或临时产物，待媒体与 final-stage 校验通过后再更新当前成片指针；失败只清理本次产物。成片、字幕、时间线和报告应属于同一个可回溯版本。
- 验收：已有成功版本时，配置缺失、配音失败、渲染失败和校验失败均不改变旧版文件及其哈希；成功重试产生新版本并可回退。
- 本轮落实：只向唯一临时 MP4 渲染和探测，报告写入成功后用同目录 rename 替换成片；失败清理只作用于本次临时视频。增加配置、TTS、部分渲染、探测异常、格式/时长校验、报告写入失败和成功替换的回归测试。
- 本轮边界：实现失败时保留旧视频及成功后替换，不实现整套产物的版本化回退；上面的完整历史版本方案保留为后续建议。

### TD-002：人工 finalize 未加载项目 .env

- 状态：已修复并验证（2026-11-12）。
- 优先级：高，影响按 README 配置后的实际生成。
- 位置：`src/cli/manual-finalize.ts`、`src/lib/video-generator/manual/final-report.ts`。
- 根因：doctor 和自动生成 CLI 调用 `loadProjectEnv`，人工 finalize CLI 直接调用 finalizer；后者默认只使用 `process.env`。
- 已复现：在隔离 fixture 放入含占位密钥的 `.env`，清除测试进程的同名环境变量。`loadProjectEnv()` 能读到配置，而 `runManualFinalizeCli` 返回退出码 1 并报告缺少密钥。测试拦截了网络，网络调用次数为 0；没有读取或写出真实密钥。
- 建议：统一 CLI 配置加载入口和覆盖优先级，使 doctor 与实际生成使用一致配置。
- 验收：仅在项目 `.env` 配置时，doctor 与人工 finalize 对配置的判断一致；进程环境覆盖规则明确且有测试；输出不包含密钥。
- 本轮落实：CLI 复用 `loadProjectEnv`，显式传递合并后的配置，进程环境优先且不修改全局环境；覆盖文件配置、环境覆盖、无文件和参数错误。真实 ffmpeg E2E 通过该 CLI 和占位 `.env` 完成最终生成。
